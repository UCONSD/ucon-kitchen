# Session 01 — Conversation Loop MVP (occupied_remodel brain slice)

Date: 2026-08-13. Mode: Light (dev role-play; no auth/RLS/persistence). Commit: `9e3fa9a`.

## Goal (narrow)

First working conversational loop — the brain, not the product. Prove end to end:
`message -> extract -> materialize -> engine NBQ -> phrase`, in-memory, on the
`occupied_remodel` happy path. Not: persistence, auth, save-resume, pretty UI.

## Outcome

The loop spine works end to end and is committed/pushed. Two real architecture bugs were
found in live role-play and fixed in-session.

## Proven (green)

- **Engine is the sole authority** for `next_best_action`; the LLM only phrases it
  (`proposed_action` removed from the schema — nothing left for the model to override).
- **Two-pass turn order**: `extractFacts -> applyCandidateFacts -> computeNextBestAction ->
  phraseResponse`. No mandate lag; the assistant acknowledges AND asks the next question in
  the same turn; no acknowledge-only dead turns.
- **Extraction**: `project_type` inferred (occupied_remodel); `primary_pain_points` /
  `primary_must_haves` split into two arrays; `layout_change` via pending-correction
  (confirm-at-medium); ZIP serviceability checked vs the San Diego allowlist.
- **Debug view**: Project State + the mandate printed each turn.

## NOT yet tested (this is half the completion criterion — do first next session)

- **Hard-floor gate**: never deliver FIRST_VALUE below the floor. UNTESTED live.
- **FIRST_VALUE delivery** + `first_value_confidence`. UNTESTED.
- **Out-of-area** (`90210` -> NEEDS_REVIEW) and **refused-budget** paths. UNTESTED.

## Findings

1. [FIXED] Engine wasn't governing the question — the LLM was steering. -> engine sole authority.
2. [FIXED] Mandate off-by-one staleness (computed pre-extraction) -> two-pass ordering.
3. [OPEN — important] **Extraction over-confidence.** The model materialized
   `project_scope = full_kitchen_project` at HIGH confidence from narrative with no scope
   evidence. This skews the budget floor (15k vs 30k) and defeats the "materialize only at
   high confidence" safety gate; it recovered only because the user later contradicted it
   (luck, not a mechanism). Fix: evidence-grounded confidence — no HIGH for a cost driver
   (scope/budget) without an explicit textual signal; absent scope signal -> `unknown_scope`
   -> `ASK_SCOPE`.
4. [OPEN — cosmetic] Ctrl+C / EOF dumps an AbortError/readline stack instead of exiting cleanly.
5. [OPEN — cosmetic] OpenAI "no credits" error is retried 3x and prints a huge stack instead
   of one clean line.
6. [ACCEPTED tradeoff] Two LLM calls per turn now (inherent to the correct extract-then-decide
   ordering). Fine with gpt-4o-mini; optimize later only if needed.

## Owed on the planning side (before next code session)

- **Reconcile Playbook 4.2 (opening triad: project context -> ZIP) vs 4.5 (NBQ ladder: P0 =
  ZIP).** They conflict when `project_type` isn't inferable. Observed: with nothing known the
  engine went `ASK_ZIP` (ladder), not `ASK_PROJECT_CONTEXT` (triad). Write one unambiguous
  rule: during the opening triad, triad order governs; P0-serviceability applies once ZIP is
  named or context is closed.
- **Tighten confidence discipline in RIM / QUAL-SCOPE-001** (finding #3): no HIGH confidence
  for a cost driver without explicit evidence.
- **Copy this session's decisions to `DECISIONS.md`**: (a) engine is the sole action
  authority; (b) two-pass `extract -> materialize -> decide -> phrase` turn order.
